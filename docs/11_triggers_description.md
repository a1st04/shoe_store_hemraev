# Отчет по практике: День 11. Триггеры и аудит

## 1. Список созданных триггеров
1. **trg_audit_price_update** (AFTER UPDATE products) — логирует изменение цены в audit_log.
2. **trg_audit_order_delete** (AFTER DELETE orders) — логирует удаление заказа.
3. **trg_update_timestamp** (AFTER UPDATE users) — обновляет поле updated_at.
4. **trg_reduce_stock** (AFTER INSERT order_items) — списывает товар со склада.
5. **trg_protect_user_delete** (BEFORE DELETE users) — блокирует удаление пользователя с заказами.
6. **trg_check_stock_quantity** (BEFORE INSERT stock_items) — проверяет количество на отрицательность.

## 2. Разница между BEFORE и AFTER
BEFORE-триггеры (5 и 6) используются для валидации данных и отмены операции через RAISE(ABORT) до того, как данные попадут в базу. AFTER-триггеры (1, 2, 3, 4) используются для действий, которые должны произойти гарантированно после фиксации изменений (логирование, обновление связанных таблиц).

## 3. Использование OLD и NEW
* В триггере на UPDATE использовались OLD.price (старая цена) и NEW.price (новая цена) для записи в лог.
* В триггере на DELETE использовался OLD.order_id, так как записи NEW уже не существует.
* В триггере на INSERT (списание остатков) использовался NEW.stock_item_id и NEW.quantity.
